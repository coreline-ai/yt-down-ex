주소 입력 → 분석 미리보기 → 형식·화질 선택 → 다운로드 → 앱 내 재생까지 연결하고, 기록 관리·자동 재시도·업데이트 복구를 제공한다. 성공은 실제 Chrome에서 저장된 영상의 재생·탐색까지 확인한 경우로 한정한다.

## 공통 진행 규칙

- 각 Phase의 자체 테스트 완료 후에만 다음 Phase로 이동한다. 발견 이슈는 해당 Phase에 기록하고 수정한다.
- 구현·테스트 체크는 실제 증거가 있을 때만 변경한다. 모의 통신, 로컬 fixture, 실제 Chrome, 외부 사이트 결과를 구분한다.
- 기존 파일·기록·설정을 마이그레이션 전 백업한다. 취소·삭제·업데이트가 기존 영상 파일을 지우거나 덮어쓰지 않도록 한다.
- 기존 TypeScript/Vite/DOM, Python 표준 라이브러리, yt-dlp/FFmpeg/ffprobe를 우선 사용한다. 필요한 역할만 분리하고 새 프레임워크나 상주 데몬은 도입하지 않는다.
- 새 의존성은 필요성과 라이선스·버전·체크섬·복구 방식을 기록한다. 앱 UI에는 사용자가 판단할 정보만 표시한다.
- 사용자가 Goal로 구현·검증·사용자 Chrome 적용을 승인했다. 완료 항목은 해당 Phase 증거로 갱신한다.

## 현재 기준과 결정 사항

- 기존 안정화 보고서: Python 31개, 확장 E2E 4개 통과. 이는 이번 변경 전 기준이며 새 기능 테스트를 추가해야 한다.
- 기존 작업 큐: 동시 실행 1개, 최대 20개. 이 제한은 유지하며 재시도 대기도 활성 작업 수에 포함한다.
- 새 설치의 기본 형식은 MP4 호환, 기존 설정은 원본 유지로 매핑해 동작을 보존한다. 첫 실행에서 선택 상태를 명확히 보여 준다.
- 호환 저장은 원본을 내려받은 후 필요할 때만 변환한다. H.264/AAC 및 호환 픽셀 포맷이면 재인코딩을 피하고 MP4 재포장·faststart를 사용한다. 무음 영상에는 음성을 임의로 생성하지 않는다.
- 별도 탭 플레이어는 확장에 포함된 HTML/JS와 `<video>`를 사용한다. 브라우저가 지원하지 않는 원본 코덱은 재생 성공으로 표시하지 않고 MP4 호환 형식으로 다시 다운로드하도록 안내한다.
- Native Messaging은 제어 메시지만 전달한다. 영상 바이트는 **127.0.0.1의 임시 포트**에서 부분 전송하며 외부 인터페이스에는 바인딩하지 않는다. 이전 MVP의 'TCP 포트 없음'은 이번 재생 기능 범위에서 변경한다.
- 플레이어가 열려 있으면 패널을 닫아도 호스트 연결을 유지한다. 플레이어/패널/활성 작업이 모두 없으면 세션·서버·호스트를 정리한다.
- 업데이트는 검증된 엔진 버전 목록과 SHA-256 잠금 정보를 앱에 포함하고 공식 배포 파일과 대조한다. 미검증 최신 버전은 표시할 수 있어도 바로 설치하지 않는다. 추천 목록 자체 갱신은 앱 릴리스에 포함한다.

## Phase 1. 계약·데이터 호환성·재생 연결 검증

### 목표

### 구현 태스크
- [x] `outputProfile`, 실제 결과 코덱/해상도/길이, `attempt`, `nextRetryAt`, 제한된 시도 이력, `playbackPosition` 및 `schemaVersion`을 정의한다. 기존 기록의 기본값·마이그레이션·구버전 복구 정책을 정한다.
- [x] hello에 확장/호스트/프로토콜 버전과 capability를 넣고, 미지원 명령은 업데이트 안내로 처리한다. 기존 256 KiB 메시지 제한과 seq 보호를 유지한다.
- [x] 명령 초안: `openPlayback`/`closePlayback`/`savePlaybackPosition`, 확장된 `inspect`/`getSnapshot`, `deleteJobs`, `checkUpdate`/`startUpdate`/`getUpdateStatus`. 설치/업데이트는 기존 45초 일반 요청과 분리된 작업 ID·상태 조회를 사용한다.
- [x] 최소 플레이어와 루프백 서버로 실제 Chrome의 영상 로드·탐색을 검증한다. 확장 권한·CSP·로컬 네트워크 접근 제약을 확인하고 필요한 설정만 확정한다.

## Phase 2. MP4 호환 저장 — 기능 1

### 자체 테스트

- [x] 원본 유지·MP3 회귀, 한글 긴 제목·동명 파일·변환 중 취소·오류 주입을 검사한다.
- [x] MP4 호환 결과는 실제 Chrome 플레이어에서 재생·탐색이 가능해야 한다. 외부 공개 샘플 최소 1건도 실제 MP4 저장을 확인한다.

### 완료 조건
- [x] MP4 옵션에서 실제 호환 영상 저장과 재생 검증 통과. OGG 원본이나 수동 변환 결과로 대체하지 않음.

### 이슈 및 수정
MP4 변환 테스트 3개(7개 실제 입력/파일명 경로), 기존 엔진 12개 회귀 및 실제 Google Chrome 플레이어 검증 통과. artifacts/phase2-chrome.log, artifacts/phase2-external/report.json에 증거. W3 MP4 외부 다운로드 4,369,172 bytes, H.264/AAC, 전체 디코딩 exit 0. 로컬 FFmpeg에 Theora 인코더가 없어 CC BY 공개 예고편 2초 발췌를 tests/media/에 출처와 함께 고정했다.

## Phase 6. 자동 재시도 — 기능 4

### 구현 태스크
- [x] 연결 리셋·다운로드 네트워크 시간 초과·일시적 5xx/429를 구분한다. 403/404·인증·인증서·형식 없음·변환 실패·파일/DB 쓰기 실패는 자동 재시도하지 않는다.
- [x] 동일 jobId 안에서 최초 실행 + 최대 3회 재시도, 기본 대기 5/15/45초 및 제한된 jitter를 적용한다. 429의 유효 Retry-After는 상한 정책과 함께 처리하고 서버 요구보다 빨리 재시도하지 않는다.
- [x] `retry_wait` 상태·시도 횟수·다음 시각·오류 이력을 DB에 저장한다. 대기 중 worker를 점유하지 않고 준비된 다음 작업을 실행한다.
- [x] yt-dlp 내부 재시도와 앱 재시도가 곱해지지 않도록 책임을 정한다. 사용자 수동 재시도는 기존처럼 새 작업으로 만들고 이전 작업과 연결한다.
- [x] 대기 취소/종료, 중복 타이머, 호스트 재시작 정책을 구현한다. Chrome 종료 시 중단 상태로 보존하며 재시작만으로 사용자 다운로드를 자동 재개하지 않는다.

### 자체 테스트
- [x] 503→성공, 연결 리셋→성공, 계속 실패하는 서버에서 시도 횟수·대기 시각·최종 상태를 확인한다.
- [x] 403/404·TLS·FFmpeg 오류는 1회 후 종료하고, 429 Retry-After 상한 초과 시 조기 재시도 없이 안내하는지 검사한다.
- [x] 재시도 직전 취소·재시작·다른 작업 병행·중복 이벤트·동명 파일 생성 방지를 확인한다. 시간은 테스트용 시계를 주입하고 실제 네트워크 재시도 E2E도 수행한다.

### 완료 조건
- [x] 무한 반복과 중복 저장 없이 회복 가능한 실패만 제한적으로 재시도함을 검증.

### 이슈 및 수정
