## 아키텍처와 책임 경계

```text
Side Panel → Extension Service Worker ↔ Native Host → yt-dlp / FFmpeg / ffprobe
                                           ↓
                                  SQLite 상태 + 사용자 파일
```

| 경로(예정) | 책임 |
|---|---|
| extension/src/panel/ | 화면·입력·상태 렌더링, 다운로드 실행 책임 없음 |
| extension/src/background.ts | Native Port 단일 관리, 요청 중계, 재연결·스냅샷 동기화 |
| shared/protocol.schema.json | 명령·응답·오류·상태 계약의 기준 |
| native/host/ | 길이 접두 JSON 통신·허용 호출자 검사·명령 분배 |
| native/jobs/ | 작업 상태·SQLite·대기열·프로세스 수명·출력 검증 |
| native/engine/ | yt-dlp 인자·진행 이벤트·FFmpeg/ffprobe 실행 |
| scripts/ | 설치·진단·제거·테스트 실행 |
| tests/fixtures/, tests/e2e/ | 로컬 미디어·HTTP 서버·통합 및 확장 테스트 |
| artifacts/ | 테스트 보고서·스크린샷·미디어 검증 정보, Git 추적 제외 |

- UI: TypeScript + Vite + 일반 DOM/CSS. 작은 MVP에 별도 상태 관리 프레임워크는 도입하지 않는다.
- Native Host: Python 3.11 이상, 표준 sqlite3/subprocess 기반. 설치 시 전용 가상환경과 절대 실행 경로를 사용한다. Python 미설치 시 진단과 설치 안내를 제공한다.
- 엔진: yt-dlp, FFmpeg, ffprobe. 사이트에 따라 필요한 JS 런타임·EJS도 진단한다. 해당 의존성이 없으면 사이트별 지원 제한을 정확히 표시한다.
- 작업 상태 원본은 호스트 SQLite, 확장은 설정과 화면 캐시만 보관한다. 호스트는 사용자별 단일 인스턴스 잠금으로 다중 Chrome 프로필의 중복 실행을 막고 충돌 시 명시적으로 알린다.
- Service Worker가 Native Port를 소유한다. 패널 종료는 포트를 끊지 않는다. 유휴 상태에서는 영구 연결을 유지하지 않는다.
- Chrome 종료/Native Port EOF 시 진행 프로세스 그룹을 종료하고 interrupted로 기록한다. 비정상 종료 후 다음 기동에서도 남은 실행 상태를 interrupted로 복구한다. 자동 재시작 대신 사용자 재시도를 제공한다.

## 통신·작업 계약
- 모든 메시지: protocolVersion, requestId, type, payload. 작업 이벤트에는 jobId, 증가하는 seq 포함.
- 명령: hello, inspect, enqueue, cancel, retry, getSnapshot, revealFile, diagnose.
- 응답: 요청 성공/실패와 오류 code/message/retryable. 비동기 이벤트: jobUpdated. 버전 불일치 시 업데이트 안내 후 실행 거절.
- enqueue는 requestId를 영속화해 재전송으로 중복 작업을 만들지 않는다. retry는 이전 작업을 참조하는 새 jobId로 생성한다.
- 상태: queued → inspecting → downloading → postprocessing → verifying → completed. 비종료 상태에서 failed/cancelled/interrupted로 전이 가능하며 종료 상태는 뒤늦은 진행 이벤트로 되돌리지 않는다.
- 완료는 프로세스 성공, 최종 파일 존재, 크기 > 0, ffprobe 결과가 선택한 영상/오디오 조건 충족일 때만 확정한다. 스트림 존재 외에 테스트에서는 실제 디코딩도 검사한다.
- Native 메시지 최대 256 KiB, 초과 메타데이터는 잘라 표시하고 snapshot은 페이지 단위로 반환한다. stdout에는 프로토콜만, 로그는 stderr/로컬 파일로 보낸다.
- 진행 업데이트는 최대 초당 4회. 크기·남은 시간이 불명확하면 추정값을 강제로 만들지 않는다. 영상 다운로드 100% 이후에도 병합/검증 중임을 표시한다.
- 동시 다운로드 1개, 대기열 최대 20개. 분석 제한 30초, 네트워크 무응답 30초, 제한된 재시도, 후처리 제한 10분을 초기값으로 두고 실제 테스트로 조정한다. 다운로드 전체 길이에 단순 30초 제한을 걸지 않는다.

## 입력·파일·설치 정책
- URL은 HTTP(S)만, 사용자정보 포함 URL·빈 값·과도한 길이·재생목록/라이브 입력은 명시적으로 거절한다. 기존 yt-dlp 사용자 설정은 무시하고 임의 명령 인자는 받지 않는다.
- subprocess 인자 배열과 shell=False, 다운로드 URL 앞 `--` 사용. 파일 이름·경로를 정규화하고 경로 이탈·심볼릭 링크 이탈·덮어쓰기를 방지한다.
- 기본 폴더 외 출력은 사용자가 설정한 절대 경로를 검사해 허용한다. revealFile은 jobId의 검증된 결과 경로만 허용한다.
- 작업별 임시 경로에서 다운로드/병합 후 같은 파일시스템 내 최종 위치로 이동한다. 취소·실패 시 자기 작업의 임시 파일만 정리한다. 기존 다운로드 파일은 제거하지 않는다.
- Chrome 권한은 nativeMessaging, storage, sidePanel, activeTab 중심. 모든 사이트 접근·cookies 권한은 기본 요청하지 않는다.
- 호스트 allowed_origins는 설치한 확장 ID로 제한. 개발 확장 ID를 고정하는 공개 manifest key와 설치 검증을 마련한다. 개인 키는 저장소에 포함하지 않는다.
- 설치 대상: 사용자 Application Support 및 해당 브라우저 NativeMessagingHosts. 관리자 권한·상주 서버·열린 TCP 포트를 요구하지 않는다.
- 설치는 재실행 가능하게 하고 기존 설정을 백업한다. 제거는 앱 소유 항목만 삭제하고 다운로드 파일은 보존한다. 테스트는 격리한 임시 설치 루트/브라우저 프로필을 사용한다.
- URL 쿼리·인증값을 로그에서 숨긴다. 기록은 로컬 저장하며 외부 분석 서비스로 보내지 않는다.

## 결정 기록과 잔여 리스크
- 엔지니어링 검토의 P1/P2 항목을 계획에 반영했다. 계획 판정은 ready이며 런타임 성공 판정이 아니다.
- macOS의 실제 CPU·설치된 도구는 Phase 1에서 확정한다. 테스트하지 않은 플랫폼 지원은 표시하지 않는다.
- 외부 사이트 변경, CAPTCHA, 요청 제한은 엔진 갱신만으로 항상 해결되지 않는다. 사용자에게 원인을 표시한다.
- 네트워크·브라우저 설치 권한이 실제 실행을 막으면 재현 로그와 완료하지 못한 검증을 보고한다.
