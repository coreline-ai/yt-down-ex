# Stash Local

Chrome 없이 자연어로 다운로드·재생하려면 **[Stash Media 독립 스킬](docs/skill-package.md)**을 사용할 수 있습니다. 필수 도구를 사용자 폴더에 자동 설치하며, Chrome 앱과 별도 기록을 사용합니다.


주소 분석 → 옵션 선택 → 다운로드 → 영상 재생을 제공하는 **macOS용 Chrome 확장 + 로컬 엔진**입니다. Stacher의 입력 흐름을 참고한 독립 구현입니다. 클라우드 서버는 필요하지 않습니다. 영상 재생 동안만 PC 내부의 `127.0.0.1` 임시 서버가 실행됩니다.

## 설치와 사용

필요 환경: macOS, Python 3.11+, Node.js 22.12+, FFmpeg/ffprobe, Google Chrome. 최초 설치 시 실행 파일이 PATH에 있어야 합니다. 이후 엔진에는 검증한 절대 경로를 저장합니다.

```sh
npm ci
npm run build
npm run install:host
```

1. Chrome의 `chrome://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램 로드**로 프로젝트의 `dist` 폴더를 선택합니다.
2. Stash Local 아이콘을 고정하고 사이드 패널을 엽니다.
3. 주소를 입력하고 **주소 분석** 또는 Enter를 누릅니다.
4. 제목·길이·화질·영상/음성·용량 정보를 확인하고 형식과 화질을 선택합니다. 원본이 제공하지 않는 정보는 **미확인**으로 표시합니다.
5. **다운로드**를 누르고 완료 후 **재생**을 엽니다.

기본 폴더는 `~/Downloads/yt-down-interface`이며 설정에서 절대 경로를 변경할 수 있습니다. 기존 파일은 덮어쓰지 않고 번호를 붙입니다. 저장 폴더에 심볼릭 링크·상위 경로 이동·엔진 설치 폴더는 사용할 수 없습니다.

## 기능

| 기능 | 동작 |
|---|---|
| MP4 호환 영상 | 새 설정의 기본값. 실제 H.264/yuv420p 영상과 AAC 음성으로 저장. 호환 스트림은 복사하고 나머지는 변환. 무음 영상에 음성을 만들지 않음 |
| 원본 유지 / MP3 | 원본 유지는 코덱에 따라 MP4 외 컨테이너가 나올 수 있음. MP3 변환은 원본 음질을 개선하지 않음. 기존 설정의 영상 모드는 원본 유지로 보존 |
| 분석 미리보기 | 제목·썸네일·길이·지원 높이·예상/정확한 용량. URL 변경 시 기존 분석을 취소하고 다른 주소의 결과가 제출되지 않도록 함 |
| 재생 화면 | 재생/일시 정지, ±10초, 탐색, 음량·음소거, 배속, 전체화면, 이어보기. Space/←/→/M/F 단축키 |
| 기록 관리 | 전체·진행·완료·실패 필터, 전체 DB의 제목/사이트 검색, 현재 목록 선택, 선택/실패 기록 일괄 삭제 |
| 자동 재시도 | 연결 종료·네트워크 시간 초과·일시적 서버 오류만 최초 실행 외 최대 3회. 대기 시간·시도 이력·취소 제공 |
| 엔진 관리 | 설정에서 버전·설치 경로·호환성 진단, 공식 배포 정보 확인, 검증 버전 설치/재설치, 이전 엔진 복원 |

**기록 삭제는 미디어 파일을 지우지 않습니다.** 실행 중인 작업은 먼저 취소해야 합니다. 재생 중인 기록을 지우면 해당 재생 세션도 종료됩니다. 완료 파일이 이동·교체되면 기존 재생 위치를 적용하지 않습니다. 영상 끝 부근의 위치는 처음으로 초기화합니다.

대기열은 최대 20개, 실제 다운로드는 1개씩 실행합니다. 자동 재시도 대기는 worker를 점유하지 않아 다음 작업을 실행할 수 있습니다. Chrome을 완전히 종료하면 작업은 중단되며 재시작만으로 자동 재개하지 않습니다.

## 재시도 정책

- 기본 대기 5/15/45초에 0~1초의 무작위 지연을 더합니다. 같은 작업에서 최대 4회 실행합니다.
- HTTP 500/502/503/504, 연결 리셋/종료와 네트워크 시간 초과가 대상입니다.
- 429는 원 주소에 redirect 없는 3초 제한 HEAD 요청으로 `Retry-After`를 확인할 수 있고 1시간 이하인 경우에만 자동 재시도합니다. 서버 요구보다 빨리 재시도하지 않습니다. 확인 불가 또는 상한 초과는 안내 후 종료합니다.
- 403/404·인증·TLS 인증서·형식 없음·변환·파일/DB 쓰기 오류는 자동 재시도하지 않습니다. yt-dlp 내부 재시도 횟수는 0으로 설정해 중첩 반복을 막습니다.
- 사용자 **다시 시도**는 이전 작업과 연결된 새 작업을 만듭니다. 바이트 단위 이어받기는 지원하지 않습니다.

## 업데이트와 복구

설정 → **업데이트 확인**으로 공식 PyPI 정보와 앱의 검증 목록을 대조합니다. 현재 검증 조합은 yt-dlp **2026.6.9**와 EJS **0.8.0**입니다. 더 최신 버전이 있어도 미검증 버전을 자동 설치하지 않습니다. 공식 wheel URL과 SHA-256은 `shared/engine-releases.json` 및 `requirements-engine.txt`에 고정되어 있습니다.

**검증 버전 설치 · 재설치**를 누르면 독립 updater가 파일 해시 확인 → 별도 venv 설치 → 도구/호환성/DB 진단 → 활성 릴리스 교체를 수행합니다. 같은 버전의 재설치도 가능합니다. 분석·다운로드·재시도 대기·재생 중이면 작업을 강제로 끊지 않고 요청을 거절합니다. 설치 중 패널은 진행 상태를 조회하고 완료 후 새 엔진에 다시 연결합니다.

- 다운로드/해시/설치/진단 실패 시 기존 활성 릴리스를 유지합니다.
- **이전 엔진으로 복원**은 직전 릴리스를 진단하고 현재 DB와 호환되는 경우에만 전환합니다. 기록 DB를 지원하지 않는 구형 엔진으로는 복원하지 않습니다.
- 설치 중 강제 종료되면 마지막으로 검증된 활성 엔진을 사용합니다. 중단 상태를 확인하고 다시 설치할 수 있습니다. 미활성 임시 릴리스가 남을 수 있지만 기존 영상·DB를 삭제하지 않습니다.
- 엔진 설치 위치의 `active.json`, `previous.json`, `update-status.json`에 활성 경로·복원 경로·작업 상태를 보존합니다.
- **이 버튼은 확장을 업데이트하지 않습니다.** 확장 소스 변경은 `npm run typecheck && npm run build` 후 Chrome 확장 관리 화면의 새로고침 버튼으로 적용합니다.

CLI 복구도 가능합니다. 다운로드와 재생을 종료하고 모든 패널·재생 탭을 닫은 뒤 15초 기다립니다.

```sh
npm run diagnose
npm run install:host
python3 scripts/install.py --rollback
```

고정 wheel을 미리 준비했다면 오프라인으로 재설치할 수 있습니다.

```sh
npm run install:host -- --wheel-dir artifacts/wheels
```

Python/FFmpeg/Node의 설치 경로를 바꾸면 호스트를 다시 설치해야 합니다. FFmpeg는 [공식 다운로드 안내](https://ffmpeg.org/download.html)를 참고하세요. 시스템 Python 환경을 수정하거나 관리자 권한을 요구하지 않습니다.

## 장애 안내

| 현상 | 조치 |
|---|---|
| 로컬 엔진 연결 필요 | 로컬 호스트 설치와 확장 ID/경로 확인 후 다시 연결 |
| 다른 Chrome 프로필이 사용 중 | 다른 프로필의 작업과 재생을 종료한 뒤 재연결 |
| 기록 저장 오류 · 대기열 멈춤 | 디스크 여유 공간·폴더 권한 확인. 모든 패널과 재생 탭을 닫고 15초 뒤 재연결. 기록 저장 직전 실패한 경우 저장 폴더에 검증된 파일이 남아 있을 수 있으므로 확인 |
| 중단됨 | Chrome/엔진 종료로 중단. 사용자 다시 시도로 새 작업 실행 |
| 재생 실패 | 파일 이동·교체 여부 확인. 원본 코덱이 Chrome에서 재생되지 않으면 MP4 호환 형식으로 다시 저장 |
| 사이트 접근 거부 | 주소의 공개 접근 가능 여부 확인. 403·로그인 요구·사이트 제한을 우회하지 않음 |
| 업데이트 중단/실패 | 진행 상태와 엔진 진단 확인. 이전 엔진 복원 또는 CLI 재설치 |

## 검증

```sh
npm run setup:tests
npm run verify
npm run test:external
npm run test:chrome
python3 scripts/long_fixture.py
STASH_LONG_TEST=1 npm run test:chrome
```

- `verify`: 타입 검사·빌드·Python 단위/실제 미디어/설치 테스트·격리 Chromium 확장 E2E. 설치 GUI E2E는 실제 공식 wheel 다운로드를 포함하므로 네트워크가 필요합니다.
- `test:external`: Blender 공개 OGG 원본을 실제로 내려받아 **H.264/AAC MP4로 변환**, 전체 디코딩·SHA-256 확인. 특정 사이트 extractor 성공이나 모든 사이트 지원을 뜻하지 않습니다.
- `test:chrome`: 독립 Google Chrome 프로필에서 실제 사이드 패널·다운로드·재생·탐색 검사. 평소 사용하는 Chrome의 Computer Use 검사와 구분합니다.
- 긴 영상은 FFmpeg로 생성한 30분 샘플입니다. 1 GiB 검사는 영상 다운로드가 아닌 합성 바이트의 Range 스트리밍/메모리 검사입니다. 1,000개 기록 테스트는 검색·커서·삭제 시간을 측정합니다.
- 파일/DB 장애는 테스트에서 주입합니다. 사용자의 실제 디스크를 채우지 않습니다.
- 증거는 `artifacts/`, 보고서는 `docs/features-validation-20260910.md`에 보존합니다. 필수 검증이 남아 있으면 전체 완료로 표시하지 않습니다.

## 데이터와 지원 범위

입력 URL·파일 경로·작업 기록·이어보기 위치는 사용자 PC의 SQLite에 저장합니다. 다운로드는 해당 미디어 서버, 업데이트 확인/파일 다운로드는 공식 PyPI에 직접 접속합니다. 별도의 분석 서버로 콘텐츠나 기록을 보내지 않습니다. 재생 토큰은 메모리에만 저장하고 URL 로그·SQLite·브라우저 설정에 기록하지 않습니다.

재생용 서버는 `127.0.0.1` 임시 포트에만 연결하며 완료 기록에 대응하는 파일만 제공합니다. 최대 16개 세션, 1시간 만료, 최대 8개 동시 요청, 64 KiB 버퍼를 사용합니다. 모든 패널·재생 탭·활성 작업이 사라지면 15초 후 호스트와 포트가 종료됩니다.

Windows/Linux, 웹 스토어 배포, 서명·공증 설치 패키지, 재생목록·실시간 방송, 로그인 쿠키 추출, DRM·접근 제한 우회는 포함하지 않습니다. YouTube 실제 다운로드는 검증하지 않았으며 모든 사이트·코덱의 성공을 보장하지 않습니다.

제거하려면 `npm run uninstall:host`를 실행합니다. 엔진과 작업 기록을 지우고 영상 파일은 보존합니다. Chrome 확장은 관리 화면에서 별도로 제거합니다.
